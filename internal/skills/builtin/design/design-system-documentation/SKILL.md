# Design system documentation

Use this skill to make design decisions stick. A documented system — tokens, components, usage rules — lets anyone build consistently without asking the original designer.

## When to use

- A product outgrows ad hoc screens.
- Handoff between designers or to developers.
- Inconsistencies multiply across screens.

## Procedure

1. Capture the product context: audience, platforms, brand constraints.
2. Document tokens: colors, type, spacing, radii, motion values.
3. Catalog components with their variants, states, and usage rules.
4. Show do-and-don't examples for the most misused pieces.
5. Version the system and note what changed per release.

## Output

A versioned design system: context, tokens, components, and rules.

## Pitfalls

- Undocumented systems decay; document or delete.
- Examples must show misuse too, not just the happy path.
