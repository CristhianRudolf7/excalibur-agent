# Classroom (personalized courses)

Contract shared by the backend, the agent tool and the web interface.

## Rules
- A course has a syllabus of topics, optionally grouped in units, created complete when the course is created. The user can edit it (add, rename, reorder, remove topics or units); progress is recomputed.
- Topics can be opened in any order. Each topic has one stored class, delivered in chat (markdown) or on the interactive whiteboard (the class keeps the whiteboard id and also a markdown version). A class can be regenerated on request.
- Every topic ends with a mandatory quiz of closed questions only: single choice, multiple choice and matching. A topic completes only when every answer of one attempt is correct. Unlimited retries; every retry is a new quiz with new questions generated by the agent. After each attempt the client shows which answers were wrong (never the correct answers) and the agent writes feedback.
- Grading happens on the server. Correct answers never reach the browser.
- The final exam unlocks when every topic is completed, has at least max(10, 2 x largest topic quiz) questions and follows the same rules. Progress is completed topics up to 99%; 100% only after the final exam is passed.
- Content language follows the user's language preference. Courses belong to the local user only.

## Conversation model
There is one agent conversation (the same one used from Telegram). The classroom header chat is a view of that conversation: messages sent from the classroom carry a context object `{app: "classroom", course_id, topic_id?}` so the agent knows where the user is, and the replies stay in the single history. The empty classroom view asks "What do you want to study?" through the same conversation.

## API (JSON-RPC, registered in internal/api and exported to packages/contracts)
- `classroom.list` -> {courses: [CourseSummary]} (id, title, progress, updated_at, topic counts)
- `classroom.get` {course_id} -> Course without answer fields
- `classroom.update_syllabus` {course_id, units} (user edits; ids kept for existing topics)
- `classroom.delete` {course_id}
- `classroom.open_topic` {course_id, topic_id} -> {topic, class?}; marks in_progress; if the class does not exist yet, asks the agent to prepare it (event `classroom.class_requested`)
- `classroom.request_quiz` {course_id, topic_id? , final?} -> asks the agent to generate a quiz (event `classroom.quiz_requested`) unless an unanswered one exists
- `classroom.get_quiz` {quiz_id} -> quiz without answers (QuestionView)
- `classroom.submit` {quiz_id, answers} -> {attempt: id, passed, results} ; server grading; then event `classroom.attempt_graded` so the agent writes feedback
- `classroom.attempts` {course_id, topic_id?} -> attempts history (with feedback)

## Events (typed bus)
`classroom.course_created`, `classroom.course_updated`, `classroom.class_requested`, `classroom.class_ready`, `classroom.quiz_requested`, `classroom.quiz_ready`, `classroom.attempt_graded`, `classroom.feedback_ready`, `classroom.topic_completed`, `classroom.course_completed`.

## Agent tool `classroom` (default surface, deferred with intent keywords: course, curso, learn, aprender, study, estudiar, class, clase, quiz, exam)
Actions: `create_course` {title, goal, level, language, units[{title, topics[{title, summary}]}]}; `update_syllabus`; `get_course`; `write_class` {course_id, topic_id, format: chat|whiteboard, content, whiteboard_id?}; `create_quiz` {course_id, topic_id? | final:true, questions[Question with answers]} (validated: kinds, option counts, correct indexes, matching is a permutation, final exam size); `write_feedback` {attempt_id, feedback}; `list_courses`.
