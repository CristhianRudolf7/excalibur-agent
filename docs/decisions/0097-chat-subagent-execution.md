# Chat subagent execution

The conversational turn path returned successful spawn records without an
engine consuming them. The daemon also inherited the embedded adapter's
record-only scope note; with SQL orchestrator stores the embedded surface
could create a separate private orchestrator. An explicit implementer profile
failed because its template level was fixed at two while the master creates
level-one children. Status accepted only `run`, and messages required agent
IDs rather than the returned run ID.

The daemon now installs its authoritative subagent tool for both store types.
A chat delegation supervisor drives each successfully spawned run only after
orchestrator admission. Profiles determine capabilities and model roles;
the parent determines the new identity's hierarchy level. Level-two agents
still cannot spawn. `run_id` is an additive alias for `run`; messages resolve
a run ID to its agent before applying the existing subtree authorization.
An omitted message type defaults to a report.

The master ends its short turn after successful delegation with a deterministic
acknowledgement. Child workers have independent, bounded contexts and use the
configured model endpoint, shared journal, file history and leases. Project
scope selects the working directory; registered roots and a sole project
provide fallbacks for general-scope cards. Children receive the delegation
card and pending mailbox messages, with profile and card tool reductions.
Generic deferred dispatch is excluded from child grants to prevent widening
those reductions. Shutdown cancels and joins workers, retaining durable runs
for the existing boot reconciliation policy.

Final reports reuse `Master.SendAssistant`, which persists and publishes the
message and derives its changes from the trusted child run ID. Delivery waits
for the conversational acknowledgement to persist. Model failures now use the
failure edge directly: routing failures through verifying previously attempted
an invalid verifying-to-failed transition. Successful outcomes retain the
verification transition. Paused executions remain attached until resumed;
cancellation interrupts the live engine and prevents subsequent file writes.

No eval tool table, public core interface, provider credential policy, or web
code changes are included. A restart still follows the existing recovery
policy; the supervisor does not automatically replay parked chat work.
